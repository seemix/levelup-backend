# Промти для виконання етапів

Як користуватися: перемкнути модель (`/model opus` або `/model sonnet`), почати нову сесію (`/clear`) і вставити промт етапу. Усі промти посилаються на спільний протокол нижче, тому кожна сесія самодостатня.

## Протокол виконання етапу (спільний для всіх)

1. Прочитай `CLAUDE.md`, `AGENTS.md`, потрібні розділи `docs/spec.md` і свій етап у `docs/plan.md`. Перевір, що попередні етапи відмічені `[x]`. Якщо ні — зупинись і повідом.
2. Уся робота — тільки в гілці `crm` (і в `levelup`, і в `levelup-front`). Перед початком перевір `git branch --show-current`. Якщо гілки ще немає — створи її від `master`. У `master` нічого не коміть, нічого не мерджи й не пуш.
3. Виконуй лише свій етап. Не роби роботу наступних етапів і не рефактор стороннього коду.
4. Якщо spec суперечливий або неповний, прийми мінімальне рішення, запиши його в `docs/spec.md` §1 (новий пункт `A..`) і згадай у підсумку. Якщо рішення суттєве (гроші, права, модель даних) — спитай мене.
5. Жодних захардкожених рядків в UI: ключі одразу в ru/ro/en.
6. Після змін схеми — `pnpm generate:types`; після нових компонентів адмінки — `pnpm generate:importmap`. Дефолти/індекси для наявних даних — міграція в `src/migrations`.
7. Перевірка: `pnpm typecheck`, `pnpm lint`, `pnpm test:int` (для фронту: `npm run lint`, `npx tsc --noEmit`). Усе має бути зеленим. Не вимикай і не послаблюй тести, щоб пройти перевірку.
8. Відміть `[x]` у `docs/plan.md` тільки для реально виконаних пунктів. Зроби коміт у гілці `crm` з повідомленням `crm(stage <N>): <коротко>` (без push і merge).
9. Підсумок для мене: що зроблено, прийняті рішення, що перевірити вручну (покроково), відомі обмеження.
